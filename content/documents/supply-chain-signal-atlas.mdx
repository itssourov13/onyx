## Provenance is an evidence chain

Dependency manifests tell you what a build declares. Provenance evidence asks a harder question: how did the artifact move from source to the thing that was deployed?

## Signals worth retaining

- source revision
- dependency resolution
- build environment
- artifact digest
- signer or attestation identity
- deployment target

## Failure mode: drift

A fictional build can pass local review while the deployment resolves a different dependency graph. The useful control is not a larger dashboard; it is a verifiable chain between source, build inputs and artifact.

## Minimal evidence model

```text
source → resolver → build → artifact → deploy
   │         │         │         │
   └──────── evidence / digest ──┘
```

SLSA and SBOM formats provide useful vocabulary for making these relationships machine-readable. The Onyx implementation keeps the records synthetic and intentionally small.
